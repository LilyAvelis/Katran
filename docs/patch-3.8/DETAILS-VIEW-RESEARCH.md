# Details View / mini-stream: architecture research

Later implementation: [Mini stream](DETAILS-VIEW.md). The research-only status
below records the earlier checkpoint before the owner's implementation request.

Status: research only, 2026-11-17. No product implementation, build or native UI acceptance is claimed. The desired third view is a dense list on the left with a preview and available metadata for the cursor item on the right. It should work across the existing shelf providers and preserve their existing commands and protections.

## Current architecture

* `src/interaction.rs`: `View` is currently `Gallery | List`, snake-case serialized. Interaction owns tab, visible IDs, cursor, selection, anchor, explicit full-screen `preview`, generation, and navigation. `preview` changes arrow handling and is not an appropriate state flag for an always-visible side panel. `visible` may move the cursor when the old one disappears; selection and cursor are not equivalent.
* `src/settings.rs`: `TabPreferences` stores view, sort, gallery columns, stream rows and compact columns per tab. `SetView` (`src/api.rs`, dispatcher in `src/lib.rs`) persists via `SetSettings`; `SetTab` restores preferences. `AdjustDensity` currently matches both variants exhaustively. `src/actions.rs` exposes gallery/list actions; `src/bin/settings_ui.rs` offers both views. Adding an enum variant requires auditing all exhaustive matches, transport compatibility, saved settings, action discoverability and shortcuts. Adding a new field to `TabPreferences` also needs a backward-compatible default: the struct denies unknown fields and is loaded for existing profiles. Older Katran may reject settings containing an unknown new enum value, so rollback/settings compatibility must be designed and tested explicitly, not assumed.
* `src/bin/ui.rs` computes columns (one for stream), handles keyboard navigation, controls lazy preview workers and passes `visible` into `src/bin/shelf_view.rs`. The shelf list uses `category_divider::layout` and viewport culling; current stream rows have a 72-pixel minimum and density 1–12, so a genuinely dense list needs its own row geometry, not merely calling the existing stream unchanged. Reuse the same browse pages, cursor and selection; preserve category dividers and cursor scrolling. Handle narrow width and independent scroll areas explicitly.
* Current full-screen preview is the `preview` branch in `shelf_view.rs`; the non-preview branch renders the shelf. It routes Pods, table, text/link/Markdown and image/file content separately. Extract a bounded presentation component where useful, but do not reimplement navigation, persistence or actions there. A split view should follow `Interaction.cursor`; use `Navigate` and `Select` as today, including multi-selection. Previewing must not mutate the selection or start Quick Look, open a URL, play video, write clipboard or trigger an action. Space/Enter/full-screen preview behavior must remain explicitly tested.
* `BrowseShelfSorted` in `src/shelf_tabs.rs` selects the catalogue, Folder, Desktop or virtual emoji provider and returns current pages/cursors. `src/workspace_service.rs::decorate_page` adds persisted properties and tags where applicable; Desktop has its own pin projection. Folder and virtual emoji are not ordinary persisted rows. Continue through these providers: do not turn a panel into a new catalogue, scan, storage, or mutating action path. Desktop cursor is bound to browse context; carry existing generation, query, sort, filter and pagination semantics unchanged.

## Existing API and asynchronous work

The common `Event` (`src/api.rs`) supplies kind, text preview (possibly abbreviated), revision, origin app/domain if recorded, ID, capture/modified times, source, name, storage, path, size and availability. Browse decorations supply applicable pinned/display-name/opener properties and tags. These fields describe what Katran recorded, not a promise that a source still exists. Empty/zero/absent or inapplicable values must not be presented as known dates, filesystem paths or sizes. In particular provenance captures a domain only when there is evidence; do not infer a page title, description, author, image or timestamp from a URL.

`src/bin/images.rs` already schedules bounded work on two read-only Service workers; pending queue is capped at 64 and keys include ID, edge and revision. `PreviewFile` can return `image`, `shell_thumbnail`, `shell_icon` or `generic_icon` with fallback reasons; `PreviewImage` is an image decoder, while `PreviewPath` supplies path plus revision for working-Folder snapshots. Surface the returned kind: a generic icon is not a file preview. `src/preview.rs`, `file_visual.rs`, `shell_visual_worker.rs` and `preview_snapshot.rs` own byte/revision checks and isolated shell extraction. Decode only the current detail item on demand; Desktop browse must stay metadata-only. A Shell thumbnail is not guaranteed, and video must not be represented as playable unless a separately verified existing route supports it.

`src/bin/text_preview_ui.rs` uses a latest-only queue and `GetDocumentText` or, for Folder files, `ReadDocumentPath` with revision; replies are checked against wanted `(id, revision)`. It displays at most 65,536 characters; Markdown reads are UTF-8 and limited to 1 MiB (`src/text_service.rs`, `preview_snapshot.rs`). `table_preview_ui.rs` similarly loads `GetTable` on a read-only worker and checks revision; grid rendering touches visible cells and source display is bounded. `DescribePod` (`src/pod_metadata.rs`) returns Unicode metadata with `metadata_truncated`, and needs an equivalent bounded, stale-safe request rather than per-frame synchronous reads in the new persistent panel. Existing full-screen code calls it through dispatcher; a side panel should not repeat it on every frame.

Link full URL is available through `GetDocumentText`; link site identity and favicon have an existing worker in `src/bin/link_card_ui.rs`. Favicons are opt-in network behavior controlled by `link_favicons_online`; reuse that choice, never fetch page content, screenshots or metadata merely to display details. `src/bin/markdown_ui.rs` paints parsed Markdown without fetching remote assets. Keep offline, loading, unavailable, stale, truncated and unsupported states distinct. Metadata means **all fields actually available and applicable**, not fabricated values.

The details request key should include provider/tab context, ID, revision and browse/view generation (and path when a Folder snapshot needs it). Negative IDs occur for different providers, including Folder, virtual emoji and Desktop; never dispatch solely from the sign of an ID. Cancel/coalesce queued work and discard late replies when cursor, revision, tab, filter or generation changes, including A → B → A with different revision. A visible fallback while loading must not expose a prior item's content as the current item. Keep bounded decoding/queues and avoid blocking UI or reading every item's content.

## Minimum API-first change

1. Add a third named `View` and wire it through `SetView`, per-tab preferences, serialization, Actions/settings and `AdjustDensity`. Decide whether it shares existing stream density or has an independently defaulted density; use a separate value if switching views must preserve both layouts. Add old-settings, round-trip, restart and backward/rollback tests. No schema migration or new storage is intrinsically required for the basic view.
2. Define the right panel's domain-facing snapshot contract before GUI work. Prefer existing decorated Browse events, `DescribePod`, `GetDocumentText`, `GetTable`, `PreviewFile`/`PreviewImage`/`PreviewPath` and `ReadDocumentPath`; test each through dispatcher using synthetic fixtures. A small unified read-only details command is warranted only if the existing API cannot obtain a consistent provider-aware snapshot; if introduced it must resolve the active context and revision rather than trusting UI-supplied paths, and return explicit unavailable/unsupported fields. Do not promise rich metadata absent from current APIs.
3. Render a compact, virtualized one-column list and a separately bounded details region, with focus and scrolling rules. Keep existing full-screen preview as a separate interaction state. Reuse standard selection, Actions and action shortcuts, visual caches and async workers; no parallel copy/delete/transfer path. Initial details follow cursor; with multi-selection, indicate that the panel describes the cursor while actions still apply to the actual selected set. Define narrow-window behavior before implementation.
4. Verify dispatcher-level behavior for all providers first, then headless layout, input and stale-worker tests, followed by Lilia's native visual acceptance. No built-in reason to invoke Quick Look automatically or start network requests.

## Provider acceptance matrix

| Provider | Existing data / preview route | Required acceptance and honest fallback |
| --- | --- | --- |
| Images | Stored `Event` and decorations; image decoder and image preview. | Image when available, recorded dimensions only if actually obtained; stale/missing bytes shown as such; retain managed-blob integrity checks. |
| Pods, saved | Text-fragment event plus `DescribePod`; `pods_ui` renders emoji and metadata. | Display text, Unicode name/codepoints and byte/unit counts; mark metadata truncation. Preserve saved-object pins/tags and revision. |
| Text | `GetDocumentText`/`GetText` worker and safe Markdown renderer. | Actual bounded text, clear truncation or read error; no arbitrary external fetch. |
| Links | Link fragment, full URL via `GetDocumentText`, display name/origin where recorded, optional existing favicon. | URL visible without claiming a live site preview; no invented page title/metadata. Honor favicon opt-in and failures. |
| Tables | `GetTable`, bounded virtualized table/CSV view. | Show supported grid and actual metadata; distinguish empty, truncated and unavailable. Existing table copy behavior remains domain-owned. |
| Files | File-reference Event; image or Shell thumbnail/icon/generic fallback, Markdown via text route. | Name/path/source/size/times only when applicable, label fallback honestly, do not open file automatically; stale/replaced original handled by existing boundary. |
| Downloads | Source projection shares Event/file visual; may have source limits. | Same as Files; no per-navigation rescans. Preserve configured source and recoverable external-original move/delete policies. |
| Screenshots | ShareX projection includes image and video references. | Images via image route, video only supported thumbnail/icon unless an existing supported preview is explicitly used; respect configured root and original-file delete boundary. |
| Desktop | `desktop_projection` Event and separate pins; image path identifies managed image despite extensionless labels. | Browse metadata-only; preview only cursor item through domain, preserve asset identity, revision and last-video deletion protection. |
| Folder | Session working-folder `BrowseShelfSorted`, negative snapshot IDs and path/revision-based `PreviewPath`/`ReadDocumentPath`. | Show actual selected snapshot; revalidate before reads and actions. Folder has no pin/tag slots (`folder_has_no_*`); do not invent them or promote paths to managed rows. |
| Virtual emoji catalogue | `pods::browse_emoji`, reserved IDs, `DescribePod`, Unicode 16 metadata. | Render emoji and real Unicode metadata; retain scoped category/filter/pagination; do not route virtual IDs to destructive, pin/tag or persistent-mutation paths. Existing copy/import, paste and Unicode drag contracts stay intact. |

## Cross-provider gates and unresolved choices

* Exercise click, keyboard up/down, range/toggle selection, filtering, paging, sort, tab switch and restored per-tab view. Verify cursor scrolling and selection remain independent, including stale/deleted cursor and empty state; no full-screen-preview arrow behavior leaks into the split layout.
* Dispatch pin, tag, copy, native drag, Folder transfer and delete through existing commands using revision-bound `SelectionRef`; preserve per-item failures and pinned guards. Folder aliases and last Desktop video retain their existing special checks; virtual emoji never reach unsupported mutation paths. Do not weaken action-boundary validation based on previously displayed metadata or thumbnails.
* Test rapid cursor/tab changes, ID reuse, source revision change, deleted/unavailable paths, old worker completions, large Unicode/text/table data, narrow window and reduced/disabled providers. Verify `visual_kind` icons are visibly identified as fallback and that offline Links cause no additional network request. For Desktop, assert browsing does not decode/hash all assets.
* Existing full-screen image zoom/pan/drag and Ctrl+arrow text/table controls depend on the preview interaction; decide which apply inside a small panel and prevent shortcuts from stealing list or text-field navigation. The panel's focus model, precise compact density, fallback at narrow widths, and metadata field priority remain product/design choices. `View` backward compatibility and any new per-tab setting need a deliberate rollback policy.
