# JSON-line wire protocol v2

`katran serve-stdio <data-directory>` accepts API version 1 and version 2 requests on the same connection. Send `api_version: 2` on each request to opt into the lossless JSON wire encoding. The response reports version 2. In-process Rust `Request` and `Service::execute` remain version 1 and retain numeric `i64` IDs; persisted IDs are unchanged.

In v2 responses, any integer outside JavaScript's safe integer range (−9007199254740991 through 9007199254740991) is a canonical decimal string, recursively in objects and arrays. Safe integers remain JSON numbers. Clients must preserve such strings exactly and treat IDs as opaque. Floating-point values are unchanged. V1 responses remain numeric and may lose precision when parsed by JavaScript.

For v2 requests, event IDs in scalar `id` or `after_id` fields, `ids` arrays, `items[].id` selection references, and screenshot match `pairs[].clipboard_id` / `pairs[].source_id` accept safe integer numbers or canonical signed decimal `i64` strings. This applies only to commands whose schema declares those fields as numeric IDs; string-valued IDs such as action and managed-asset IDs remain strings. The rule also applies inside `begin_job.command` and `ingest_with_origin.command`. Numbers outside the safe range, noncanonical strings, out-of-range strings, and non-integers are rejected as `invalid_request`; an already-rounded JavaScript number cannot be recovered. `poll_job.job_id` and `cancel_job.job_id` similarly accept safe unsigned integer numbers or canonical unsigned decimal `u64` strings; unsafe numeric forms are rejected. The same unsigned rule applies to overlay and drag `owner_window` and to `capture.previous.hwnd` and `capture.previous.process_started` in overlay receipts. Other input fields keep their existing types, including numeric fields unrelated to identities.

The v2 mapping is explicit. When adding a command with numeric ID fields, update `api_wire_v2.rs` and its tests as part of the command contract. This version negotiation applies to the stdio transport; direct Rust clients continue to use the v1 API.
